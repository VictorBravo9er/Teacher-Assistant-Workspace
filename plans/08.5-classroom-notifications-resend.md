# Plan 08.5: Universal Classroom Notifications, Resend Delivery Engine & Bounce Tracking

## 1. Problem Statement & Scope
While [Plan 08](./08-extended-lms-modules.md) establishes in-app announcement feeds and academic calendars, educators and students lack automated email notifications for core classroom lifecycle events:

1. **Course Announcements**:
   - When teachers broadcast critical updates (rescheduled exams, room changes), students and parents may not check the portal in time.
2. **Material Publishing & Updates**:
   - When teachers publish new homework assignments, syllabus notes, or lab sheets in [`AddMaterialModal.tsx`](file:///home/victor/antigravity/Teacher-Assistant-Workspace/frontend/src/features/classroom/AddMaterialModal.tsx) or update existing materials, enrolled students receive no notification.
3. **Student Assignment Self-Turn-In**:
   - When students turn in assignments in [`StudentTurnInModal.tsx`](file:///home/victor/antigravity/Teacher-Assistant-Workspace/frontend/src/features/student-portal/StudentTurnInModal.tsx), teachers have no email notification that new submissions await review in their grading queue.
4. **Delivery Transparency & Undelivered Bounce Alerts**:
   - In-app toasts must not falsely claim "delivered" when emails are merely dispatched to the MTA.
   - If a student's or parent's email address is invalid or bounces, the teacher must receive an **automated alert email** informing them of the failure so they can update the student's contact details.

## 2. Target Architecture: Multi-Event Resend Notification Pipeline

```
 Classroom Events                                           Edge Functions & Resend                                        Recipients
─────────────────                                           ───────────────────────                                        ──────────
1. Teacher Posts Announcement ────────┐
   (ClassDetails.tsx)                 │
                                      ├──► supabase/functions/notify-announcement ──► Resend Batch API ─────────► Enrolled Students & Parents
2. Teacher Publishes/Updates Material ├──► supabase/functions/notify-material     ──► Resend Batch API ─────────► Enrolled Student Roster
   (AddMaterialModal.tsx)             │
                                      │
3. Student Turns In Assignment ───────┴──► supabase/functions/notify-submission   ──► Resend Email API ─────────► Course Teacher (Single)
   (StudentTurnInModal.tsx)                         │
                                                    ▼
                                     Logs to public.notification_logs ('queued')
                                                    │
                                                    ▼ (Asynchronous Delivery / Bounce)
                                           Resend Webhook Event
                                                    │
                                                    ▼
                                     supabase/functions/resend-webhook
                                                    │
                                       ┌────────────┴────────────┐
                                       ▼                         ▼
                              status: 'delivered'       status: 'bounced'
                                                                 │
                                                                 ▼
                                                        Dispatches Alert Email
                                                        to Teacher's Inbox ⚠️
```

## 3. Implementation Steps

### Step 3.1: Centralized Notification Audit Schema ([`schema/schema-db.sql`](file:///home/victor/antigravity/Teacher-Assistant-Workspace/schema/schema-db.sql))
Create `public.notification_logs` to record all email dispatches, Resend IDs, and asynchronous delivery states across all classroom events:

```sql
CREATE TABLE IF NOT EXISTS public.notification_logs (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    class_id UUID NOT NULL REFERENCES public.classes(id) ON DELETE CASCADE,
    announcement_id UUID REFERENCES public.announcements(id) ON DELETE CASCADE,
    material_id UUID REFERENCES public.materials(id) ON DELETE CASCADE,
    submission_id UUID REFERENCES public.student_submissions(id) ON DELETE CASCADE,
    notification_type TEXT NOT NULL CHECK (
        notification_type IN ('announcement', 'material_published', 'material_updated', 'submission_turned_in')
    ),
    recipient_email TEXT NOT NULL,
    recipient_name TEXT,
    recipient_type TEXT NOT NULL CHECK (recipient_type IN ('student', 'parent', 'teacher')),
    student_id UUID REFERENCES public.students(id) ON DELETE SET NULL,
    resend_email_id TEXT, -- ID returned by Resend API (e.g. re_xxxx)
    status TEXT NOT NULL DEFAULT 'queued' CHECK (status IN ('queued', 'delivered', 'bounced', 'failed', 'complained')),
    error_message TEXT,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- Index foreign keys and search columns for performance
CREATE INDEX IF NOT EXISTS idx_notification_logs_class_id ON public.notification_logs(class_id);
CREATE INDEX IF NOT EXISTS idx_notification_logs_announcement_id ON public.notification_logs(announcement_id);
CREATE INDEX IF NOT EXISTS idx_notification_logs_material_id ON public.notification_logs(material_id);
CREATE INDEX IF NOT EXISTS idx_notification_logs_submission_id ON public.notification_logs(submission_id);
CREATE INDEX IF NOT EXISTS idx_notification_logs_resend_email_id ON public.notification_logs(resend_email_id);

-- RLS: Teachers can view and manage notification logs for their classes
ALTER TABLE public.notification_logs ENABLE ROW LEVEL SECURITY;

CREATE POLICY "Teachers view notification logs for their classes"
    ON public.notification_logs FOR ALL
    USING (EXISTS (
        SELECT 1 FROM public.classes 
        WHERE classes.id = notification_logs.class_id AND classes.user_id = auth.uid()
    ));
```

### Step 3.2: Edge Function: Announcement Notifications ([`supabase/functions/notify-announcement/index.ts`](file:///home/victor/antigravity/Teacher-Assistant-Workspace/supabase/functions/notify-announcement/index.ts))
- Receives `{ announcement_id, notify_parents }`.
- Verifies teacher ownership via JWT.
- Fetches enrolled students (`students.email`) and parents (`class_students.parent_contact`).
- Formulates personalized payloads (`Hi Liam,` vs `Dear Margaret,`).
- Dispatches batch in chunks of 100 via `https://api.resend.com/emails/batch`.
- Logs records with status `'queued'` and associated `resend_email_id`.

### Step 3.3: Edge Function: Material Published / Updated Notifications ([`supabase/functions/notify-material/index.ts`](file:///home/victor/antigravity/Teacher-Assistant-Workspace/supabase/functions/notify-material/index.ts))
When a teacher publishes or updates a learning material:
- Receives `{ material_id, class_id, event_type: 'published' | 'updated', notify_parents?: boolean }`.
- Verifies teacher ownership.
- Fetches material details (title, category, due date `due_at`, description).
- Dispatches personalized batch emails to enrolled students:
  - **Subject**: `[${classTitle}] ${event_type === 'published' ? 'New' : 'Updated'} ${material.category}: ${material.title}`
  - **Body**: Includes category badge, assignment deadline (if applicable), summary, and direct link `Open in Student Portal`.
- Logs rows into `public.notification_logs` with `notification_type: 'material_published' | 'material_updated'`.

### Step 3.4: Edge Function: Student Submission Turn-In Notifications ([`supabase/functions/notify-submission/index.ts`](file:///home/victor/antigravity/Teacher-Assistant-Workspace/supabase/functions/notify-submission/index.ts))
When a student turns in an assignment in [`StudentTurnInModal.tsx`](file:///home/victor/antigravity/Teacher-Assistant-Workspace/frontend/src/features/student-portal/StudentTurnInModal.tsx):
- Receives `{ submission_id, class_id }`.
- Verifies caller is the student enrolled in the class.
- Resolves student name, submission details, material title, and teacher email (`classes.user_id -> auth.users.email`).
- Dispatches email to teacher via Resend:
  - **Subject**: `[Turn-In] ${studentName} submitted ${materialTitle} (${classTitle})`
  - **Body**:
    ```html
    <div style="font-family: sans-serif; max-width: 600px; margin: 0 auto; padding: 24px; border: 1px solid #e5e7eb; border-radius: 8px;">
      <h3 style="color: #4F46E5; margin-top: 0;">${classTitle}</h3>
      <h2>Assignment Submission Received</h2>
      <p><strong>${studentName}</strong> has turned in work for <strong>${materialTitle}</strong>.</p>
      <p style="font-size: 13px; color: #6B7280;">Submitted on: ${new Date().toLocaleString()}</p>
      <div style="margin-top: 24px;">
        <a href="${appUrl}" style="background-color: #4F46E5; color: #ffffff; padding: 10px 18px; border-radius: 6px; text-decoration: none; font-size: 13px; font-weight: 500; display: inline-block;">Open Grading Queue</a>
      </div>
    </div>
    ```
- Logs row into `public.notification_logs` with `notification_type: 'submission_turned_in'`, `recipient_type: 'teacher'`.

### Step 3.5: Edge Function: Resend Bounce & Delivery Webhook ([`supabase/functions/resend-webhook/index.ts`](file:///home/victor/antigravity/Teacher-Assistant-Workspace/supabase/functions/resend-webhook/index.ts))
Handles asynchronous delivery status updates from Resend:
- **On `email.delivered`**: Updates `public.notification_logs.status` to `'delivered'`.
- **On `email.bounced` or `email.failed`**:
  1. Updates `notification_logs.status` to `'bounced'` and records `error_message`.
  2. Queries the class teacher's email from `classes.user_id -> auth.users.email`.
  3. Dispatches an **immediate alert email to the teacher's inbox**:
     - **Subject**: `[Delivery Failure] Notification undelivered to ${recipient_name} (${classTitle})`
     - **Body**: Explains which student or parent email bounced, the bounce reason, and prompts the teacher to update the contact details in the class roster.

### Step 3.6: Frontend Service Layer & UI Wiring
1. **Service Layer** (`frontend/src/services/notificationService.ts`):
   - `notifyAnnouncement(announcementId, notifyParents)`
   - `notifyMaterial(materialId, classId, eventType, notifyParents)`
   - `notifySubmission(submissionId, classId)`
2. **Teacher UI Controls**:
   - In `ClassDetails.tsx` (Announcements tab): `[x] Send Email Notification`, `[ ] Notify Parents`.
   - In `AddMaterialModal.tsx` & `MaterialEditModal`: `[x] Notify enrolled students via email`.
   - Honest toast feedback: *"Notification emails queued for delivery."*
   - Delivery badge pills on announcement cards (`24 queued`, `⚠️ 1 bounced`).
3. **Student UI Controls**:
   - In `StudentTurnInModal.tsx`: Upon submitting, triggers `notifySubmission(submission.id, classId)`. Toast: *"Assignment submitted successfully. Teacher has been notified."*

## 4. Verification Plan

### Automated Verification:
- Run `npm run build` in `frontend/` to confirm all types and service functions compile cleanly.

### Manual Verification:
1. **Announcement Batch Email**:
   - Teacher posts announcement with email notification checked.
   - Verify toast displays: *"Announcement posted. 24 notification emails queued for delivery."*
   - Verify Resend dashboard displays batch emails queued with personalized greetings.
2. **Material Publish Notification**:
   - Teacher uploads a new syllabus or homework assignment and checks `[x] Notify enrolled students`.
   - Verify students receive an email with material title and direct portal link.
3. **Student Turn-In Notification**:
   - Student submits homework in the Student Portal.
   - Verify that the course teacher receives an immediate email: `[Turn-In] Liam Chen submitted Lab Report 3`.
4. **Bounce Simulation & Teacher Alert**:
   - Trigger a simulated `email.bounced` event to `resend-webhook`.
   - Verify `notification_logs` status updates to `'bounced'`.
   - Verify that the teacher receives an alert email: `[Delivery Failure] Notification undelivered to Liam Chen (invalid address)`.
